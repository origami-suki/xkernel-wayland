上述顺序是当前候选，不预先承诺逐个都要改。每完成一项就复看首帧和 syscall 分布，避免优化已经不再重要的路径。

每项保留最小闭环：现象和分段数据 → 一个明确假设 → 最小改动 → 相关功能回归及实际原页显示 → 同配置对比。定位时可先用单轮诊断；正式性能收益仍须有项目规定的原始 before/after，不能拿带统计运行与不带统计运行直接算补丁收益。单纯改善 syscall CPU 排名而未改善目标指标，要如实报告。

若定位到疑似内核缺陷，按 AGENTS.md 先查配置的 x-kernel 上游相关 issue/PR；候选补丁独立获取和验证，不整体更新固定版本。不修改 Chromium、Weston、运行库或官方测试页来绕过问题。
