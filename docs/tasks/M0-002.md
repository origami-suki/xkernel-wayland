# M0-002：工具链、工作镜像与可重复串口启动

- 目标：落实 ENV-01，得到真正执行于 x-kernel 的交互 shell 和可重复运行入口。
- 依赖：M0-001 输入校验；M0-005 系统 QEMU。先读 roadmap、内核 AGENTS 和 build-workflow，以实际源码纠正文档路径。
- 范围：构建依赖、平台配置、工作盘、启动/停止封装、日志与 monitor；不实现浏览器兼容接口。
- 已知：Rust 1.95.0 已在 rustup 列表中；组件、目标、musl 交叉工具和 rust-objcopy 仍须逐项核验。上游说明中的 defconfig 路径过时。

## 执行与验收

1. 记录主机、工具路径/版本；检查 Rust targets/components、构建实际要求的交叉工具。缺哪个补哪个，不主动更新内核/浏览器。
2. 保留离线调查的只读解压镜像，为运行建立可写副本，例如 `work/images/xkernel-run.img`；记录原始和工作副本生成步骤、初始哈希，不对 Assets 或审计镜像写入。
3. 在内核目录按以下经源码核对的入口配置/构建。以下为**计划命令，本轮未运行**：

   ```sh
   cp platforms/kplat-aarch64/qemu_defconfig .config
   make defconfig
   make build
   make run ACCEL=n MEM=2g SMP=4 VSOCK=n DISK_IMG=/absolute/path/to/work/images/xkernel-run.img
   ```

   `VSOCK=n` 用于当前本地串口/monitor 闭环，避免无关 host vhost-vsock 权限/模块依赖；若改用该通道须记录原因。NET/BLK、CPU、机型、TCG 线程、图形/输入和显示后端均记录最终展开参数，不能只保存 Make 命令。不要仅凭 `ACCEL=n` 文本声称命令实际用了 TCG。
4. 运行封装应固定 `/usr/bin` QEMU、独立串口日志、monitor socket、运行编号和有界超时；核对 `bundle.toml`、ELF/Build ID、配置和 submodule 提交。`justrun` 只消费已确认的构建。
5. 连续两次从明确镜像状态启动：打印内核标识，进入 shell，执行 `uname -a`、读取根目录、创建/读取/删除临时文件；保存退出/停止原因。不能把 QEMU 停在 `-S` 的设备 smoke 当作 guest 启动通过。
6. 使用 monitor 执行一次 `screendump`（纯串口阶段若无 scanout，应如实记录无显示；在图形入口补上）；验证监控通道能接收查询和停止。首次 guest 图形证据必须重新采集。

## 失败分层与证据

依次区分构建工具、装载内核、ext4 挂载、musl loader、init/shell。官方镜像使用 ext4 64bit/metadata checksum；先记录具体失败日志再决定修复，不能靠另一份 rootfs 成功关闭本任务。

证据预留 `artifacts/runs/<run-id>/`：主机/版本、完整命令、镜像来源、配置、串口、monitor 输出、退出码、哈希。执行后将实际命令及结果填入本卡。

## 学习实验
