# M0-003：复用赛方 rootfs 并补齐 Wayland 用户态

- 目标：在赛方 rootfs 的工作副本内补齐 Weston 和必要依赖、会话配置，保留已有 Chromium/运行库，形成可重建的 Wayland 用户态。
- 已定路线：用户已确认 Wayland + 复用现有 rootfs；不需要再做 X11/Wayland 比较或等待路线批准。
- 前置：离线包/依赖清单可先准备；guest 动态探测依赖 M0-002 的可操作 shell。Linux 对照 M1-001 可并行准备。
- 已完成输入：[rootfs 调查](../analysis/rootfs-and-memory.md)、[内核能力](../analysis/kernel-capabilities.md)。镜像是 Xorg/JWM/Chromium，无 Weston；不重复做无目的全盘扫描。
- 范围：补包清单与工作镜像生成、版本/动态依赖、Wayland 会话入口、官方页部署和能力探测。DRM/Weston 显示验收进入 M2-001，接口修复独立提交。

## 分层验证

1. 从包数据库核对原有 Alpine 3.22/aarch64、musl、Chromium 及库版本。检查对应仓库中 Weston、DRM 后端、pixman renderer、最小客户端，以及该构建需要的 libseat/seatd 等包的实际名称和依赖；版本匹配有疑问时查相应官方文档。保存包来源、精确版本、签名/哈希、求解结果，不猜包名或直接执行全量升级。
2. 从原始压缩包生成可写工作副本，在该副本中增量安装并保存变更清单、配置和重建脚本。跨架构准备采用可核验的 guest/Linux 对照或离线包方式，不直接在 host 执行 AArch64 安装脚本。已有浏览器和运行库优先复用；依赖冲突先定位，不直接换一份 rootfs。
3. 验证 BusyBox、musl loader、Weston、Chromium 能否执行；记录 `--version`/内置帮助、实际模块、递归依赖、缺库/信号/退出码/超时。及早收集提供的 Chromium 原生 Wayland/Ozone 能力证据，不能只凭版本或包名断言支持；本卡允许结论为“静态证据已收集，实际连接待 M3”，不反过来依赖 M2 的 compositor 已跑通。
4. 部署三个原始测试页到独立目录并核对 host/guest 哈希，指定官方 index URL。保留原 kiosk 欢迎页及 X11 脚本作为来源记录，新增 Wayland 会话入口，不自动启动 `x11-session`。
5. 准备 `/dev/shm`、Wayland socket、`XDG_RUNTIME_DIR` 的所有者/权限和 `WAYLAND_DISPLAY`，核对 Weston 与 Chromium 的运行用户及访问权限。先从串口分层启动，成功后再接入 BusyBox 会话管理，保留退出原因，不让 respawn 遮蔽失败；不让 DHCP/NTP 阻塞离线原页。
6. 列出 `/dev/dri`、`/dev/input`、`/dev/tty*`、`/sys`、`/proc`，记录 Weston 的 seat/device 发现方式。QEMU 显式附加已验证可加载的 virtio GPU/keyboard/mouse；guest 枚举和 libinput 可用性仍需验证。VT/KD 是否需要由选定 seat 后端实际调用决定。
7. Linux 对照从同一 Wayland 工作镜像版本派生，使用相同用户态、页面、分辨率与参数。先排除缺包/用户态配置；M1-004 提供 stream fd + mmap 前置验证，M2-001 验证 Weston DRM/pixman 与最小客户端。headless/nested 成功只能关闭对应诊断项。

成功时记录成功链；失败时记录首个阻塞、排除项和下一项验证。实际接口修复进入 M1-002 或 M1-004，一项语义一个提交。工作镜像新增文件/包与内核行为改动分别提交。

## 验收与记录

- 可验收结果：从赛方原盘可重建的增量步骤、包/配置/依赖与设备清单、原页哈希、Weston/Chromium 能力探测结果；不能把只写了计划当作补包完成，不要求此卡内打通整个浏览器。
- 实际执行：仅离线调查与方案修订，未下载/安装 guest 包或创建运行会话。
- 实现状态：原镜像调查已验证，增量准备/动态部分未开始。
- 证据状态：静态齐全，运行缺失。
- 路线决定：已确认 Wayland + 复用 rootfs；用户学习/任务验收：待完成。

## 学习实验

在 guest 只启动 Weston，观察 Wayland socket、运行用户、DRM/input fd；再启动 wl_shm 客户端。将“用户程序能链接运行”“fd/协议连接成功”“真正显示像素”三个成功标志分别写下来，说明新增组件如何复用原来的 libc、字体和文件系统。
