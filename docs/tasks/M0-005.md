# M0-005：统一系统 QEMU 并移除旧版安装

- 目标：卸载遮蔽系统命令的 QEMU 5.2.0；默认使用现有系统新版，并保留项目需要的镜像、GPU、输入和显示能力。
- 范围：宿主机 QEMU 安装、配置清单、项目检查、说明及环境证据。不改内核，不运行赛方 rootfs，不修改 Assets。
- 前置依赖：M0-001 的环境与输入清单；不依赖 guest 启动成功。
- 用户条件：直接使用系统中的新版、允许卸载 5.2.0。现场 `/usr/bin` 实际为 **11.1.1**，系统包版本 **11.1.1-4**，不是口述的 11.0；使用现有版本，不另行降级。
- 状态：实现已验证；证据齐全（本机 artifacts，需随阶段材料备份）；用户学习/阶段验收待确认。

## 依据、卸载边界与残留

旧默认命令位于 `/usr/local/bin`，无 pacman 归属，版本 `5.2.0 (v5.2.0-dirty)`。原构建目录 `/home/origami/Workspace/Study/QEMU/build` 的 `meson-info/intro-projectinfo.json` 明确为 QEMU 5.2.0，`meson-logs/install-log.txt` 列出 195 个安装文件。另有 8 个 `qemu.mo`，均与该构建目录 `po/*.gmo` 内容一致。

总计移除 **203 个文件，1,963,736,025 字节**：系统/用户态模拟器、镜像工具、helper、固件、keymap、图标、desktop 文件和 locale。先保存清单、大小和逐文件 SHA-256，再核对无包归属、仍位于 `/usr/local`、内容未变化后逐项删除；只删除 `/usr/local/share/qemu` 下清空的目录，没有递归清理其他组件。原始 Meson 清单与实际卸载列表见 `artifacts/qemu-migration/`。

202 项与保留的构建产物完全一致；唯一不同的 `qemu-system-x86_64`，已确认安装项仍为 2025-08 的 5.2.0，构建产物则是 2026-03 重编的 `5.2.0-2-gf73b262a70-dirty`。它仍属于用户要求卸载的旧版本，差异证据单独保留。未删除原研究目录及构建产物，也没有在仅剩约 24 GiB 的 home 中另存全量旧二进制备份。

`/usr/local` 下 QEMU / virtfs / ivshmem 名称扫描已无残留。旧 user-mode 模拟器随 5.2.0 卸载，未额外安装本项目不需要的 `qemu-user`。本任务没有修改 PATH、shell 配置或系统包版本；原有 `/usr/bin` 命令自然成为默认。

## 实际命令与结果

```sh
# 安装来自系统现有软件仓库；未执行全系统升级
sudo -n pacman -S --needed --noconfirm qemu-img
sudo -n pacman -S --needed --noconfirm \
  qemu-hw-display-virtio-gpu qemu-hw-display-virtio-gpu-pci qemu-ui-gtk
# 卸载脚本包含清单、哈希、路径及包归属的前置检查
sudo -n python3 artifacts/qemu-migration/uninstall-old-qemu.py
zsh -lc 'rehash; type -a qemu-system-aarch64 qemu-system-x86_64 qemu-img qemu-io qemu-nbd'
qemu-system-aarch64 --version
qemu-system-aarch64 -display help
qemu-system-aarch64 -device help
python3 scripts/check_project.py --verify-assets
```

- 默认路径与所有上述核心命令版本 PASS：均为 `/usr/bin`、11.1.1；`/bin` 是同一系统入口。
- `pacman -Qk` 对核心包及新增图形模块检查 PASS，0 个缺失文件；新增包只有 qemu-img 与四个 QEMU 图形模块。
- `qemu-img create -f qcow2 <临时文件> 1M`、`qemu-img check`、`qemu-img info --output=json` PASS；临时文件已清理。
- 项目检查 PASS，包括内核锁定提交、QEMU 版本、rootfs / testpages / 赛题 PDF 完整 SHA-256。
- 新版 AArch64、TCG、2 GiB、4 vCPU monitor smoke PASS；CPU 为 `cortex-a72`，此处只用于宿主设备验证，不变更后续 guest CPU 选择。
- 非 TTY 的 `zsh -lic` 曾触发用户 shell 提示符插件 `gitstatus` / `compdef` 初始化警告，但默认路径验证有效；改以无交互 `zsh -lc` 再验 PASS，未改用户 shell 配置。

GPU / 键鼠真实加载与 monitor `screendump` 验证使用以下完整参数：

```sh
/usr/bin/qemu-system-aarch64 -machine virt -accel tcg -cpu cortex-a72 \
  -m 2G -smp 4 -S -display none -serial none -monitor stdio -nodefaults \
  -device virtio-gpu-pci -device virtio-keyboard-pci -device virtio-mouse-pci
# 在 (qemu) monitor 输入：
info version
info status
info qtree
screendump /home/origami/Workspace/Competition/ICT/XKernelGUISupport/artifacts/qemu-migration/virtio-gpu-smoke.ppm
quit
```

QEMU 正常退出，`info qtree` 包含 GPU、keyboard、mouse 三个设备，生成有效 **640×480 P6 PPM**。这是宿主模拟器与截屏链路证据：CPU 暂停且未加载 guest 内核，图像不证明 x-kernel / Chromium 已渲染。GTK 在 `-display help` 中可用，本任务未打开 GTK 桌面窗口。

## 学习实验与未完成项

亲手执行上面的无 guest GPU smoke，在 monitor 里运行 `info qtree` 与 `screendump`。观察 `virtio-gpu-pci` 下的 virtio-gpu、键鼠设备及生成的图像，再执行 `qemu-system-aarch64 -display help`。这能区分三个接口：设备模型向 guest 暴露硬件，GTK 把宿主显示结果呈现为窗口，monitor 直接导出 QEMU display surface；安装 GTK 本身不会提供 guest 的 DRM 驱动或 compositor。
