# M0-007：AI 可调用的 QEMU/GDB 现场采集

- 目标：在既有 AArch64/TCG/2 GiB/4 vCPU 运行入口上，按需采集各 CPU 的栈、寄存器、指令及指定表达式；失败现场可追溯，采集后恢复执行。
- 范围：宿主 Python 运行/诊断脚本、针对性测试及使用说明；不修改内核、用户态或 Assets。
- 依赖：M0-002 运行封装与当前内核匹配的 `kernel.debug.elf`。
- 条件：独立 Unix socket、工作盘快照、调试 ELF 内容校验与归档；调试耗时单独记录，调试运行不得用作性能样本。
- 验收：真实 QEMU 连接、暂停/恢复、多次快照、表达式失败、取证超时恢复、guest 超时自动取证；普通启动回归与证据检查。

## 实现与验证记录

原有未提交文档改动保存在 `artifacts/gdb-m0-007/pre-existing.patch`，本任务不纳入这些改动。

### 实现

- `scripts/run_guest.py --gdb`：保持原配置，增加私有 Unix socket；核对并归档匹配的调试 ELF。由主循环处理快照请求，guest 超时后退出前自动采集。
- `scripts/gdb_capture.py --run <证据目录>`：请求各 vCPU 回溯/寄存器/指令及指定表达式；逐命令记录成功/失败，GDB 超时仍恢复原状态。无 guest 写内存、写寄存器或函数调用权限。
- 调试过程排除的宿主耗时独立记录，调试运行禁止作为性能样本。通过原子 JSON 发布请求和结果，避免读取半写元数据。
- `tests/test_gdb_capture.py`：同尺寸错误 ELF/源码行表/地址、GDB 超时、原来已暂停、恢复失败和输入边界回归。
- 使用方式、证据字段和诊断限制见 [调试指南](../debugging.md)。

### 限制

这是调试工具的主机/guest smoke 验证，不是 Chromium 故障根因验证、完整图形回归或性能结果。没有内核改动，因此未重跑内核构建/单测。release 内联与启动汇编使部分回溯尾部出现 `??` 或展开终止提示，保留原文；已证明能定位到 Rust 函数/文件/行，不能声称全部调用栈完整。GDB 的 threads 表示四个 vCPU，guest 任务与 Chromium 线程还需按数据结构另行分析。

独立代码审查及修正后复审均已完成：两项问题闭环，未发现其他必要修正。复审核对归档脚本/哈希、原始 monitor 状态顺序、暂停场景寄存器相等及 25 项测试日志；属于独立代码/证据审查，没有将主 Agent 的 QEMU 实测冒充独立运行验证。
