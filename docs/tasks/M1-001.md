# M1-001：同一 Wayland 用户态的 Linux system 对照

- 目标：使用同一赛方派生工作盘建立可重放的 Linux system 启动和退出码对照，排除 ELF/用户态本身无效；后续复用到 Weston/Wayland 接口诊断。
- 前置：M0-003 的 `work/images/wayland-m0.img`；M1-002 的用例盘仅新增 `/opt/ict-tests/elf-layout`。
- 本轮范围：串口 shell、原 Chromium/Weston/seatd 版本、runner 正反例、大型 PIE 与畸形 ELF。尚未进行 Linux Weston DRM 会话/Chromium Wayland 真连接；不因此宣称 M2/M3 通过。
- 状态：**最小 Linux system 对照已验证；图形会话对照随 M2/M3 继续。** 用户阶段验收待完成。

## 启动链与参数

`scripts/run_linux_guest.py` 从指定工作盘只读提取 `/boot/vmlinuz-lts` 与 `/boot/initramfs-lts`，使用盘内原配 **Linux 6.12.110-0-lts**。前者是 ARM64 EFI gzip zboot，gzip payload offset=52552，解出具有 ARM64 Image magic 的 37,552,128 字节 Image；不能把 EFI zboot 未经验证直接视作 QEMU `-kernel` 的 raw Image。

原 initramfs 已包含 virtio-pci/blk/gpu/input、ext4 和匹配模块，`/init` 最后硬编码 `switch_root /sysroot /sbin/init`。为取得有界且无登录/respawn 的诊断 shell，runner 在保存的派生 initramfs 中仅将目标改为 `/bin/sh`；其他 newc 条目逐字节保留。原 initramfs、原/派生 init、派生 Image、哈希均随 run 保存，不改基盘。Linux 以 PID 1 shell 执行用例后 `sync; poweroff -f`，避免直接退出 PID 1 导致 Linux panic；这与 x-kernel 自己的 PID 1 退出关机机制分别记录。

固定 QEMU `/usr/bin/qemu-system-aarch64` 11.1.1、`virt,gic-version=3`、`cortex-a76`、`tcg,thread=multi`、2 GiB、4 vCPU。设备与 x-kernel runner 相同：virtio-blk-pci、rng、gpu、keyboard、mouse，离线、无网卡、serial/monitor socket、`-snapshot`。Linux 特有启动参数为 `console=ttyAMA0 root=/dev/vda rw` 和盘内 initramfs，原因是 Linux 根盘/驱动和初始 shell 启动链与 x-kernel 不同。每次查询 monitor `info status/version/qtree` 并核对 `/proc/PID/cmdline` 与计划 argv 一致。

运行记录保存 host 信息、两个仓库 commit/status、脚本、完整命令、输入/产物 SHA256、串口/monitor/QEMU 原始日志、guest/QEMU/runner 三种退出码、退出原因及基盘前后 hash。盘内没有调试版 Linux ELF，因此明确只保留原 zboot 与准确派生 Image，不声称具备 Linux DWARF；x-kernel 的调试 ELF 由其 runner 独立归档。

## 已执行验证（2026-09-24）

| 运行目录（均在 `artifacts/runs/`） | 结果 |
| --- | --- |
| `m1-linux-smoke` | 同一 Wayland 工作盘到 shell，`uname` 为 6.12.110-0-lts，getconf 核对 4 CPU，`true` 成功，guest/QEMU/runner 均 0 |
| `m1-linux-versions` | Chromium 142.0.7444.59、Weston 14.0.2、seatd 0.9.1 均 exit 0；guest/QEMU/runner 均 0 |
| `m1-linux-failure` | 显式 `false` 为 guest 1，仍正常 poweroff/QEMU 0，runner 1；证明 QEMU 0 不掩盖命令失败 |
| `m1-linux-elf-positive` | small-pie、80 MiB BSS large-pie、static-exec 均 `ELF_LAYOUT_OK`，supervisor 存活、child exit 0；同盘 Chromium `--version` exit 0 |
| `m1-linux-elf-invalid` | 六项错误 ELF 均采集到独立 errno/signal，父进程存活，随后正常关机；此 run PASS 表示观察完整，**不表示六项都返回 execve errno**，详见下表 |

所有运行均在关机后重新校验基盘 hash 不变。普通 Wayland 盘 SHA256=`3b97a851dbb672a241ce1921625adc5aed9f806ccb297bc5f39be04fb3b3f32d`。本轮 Linux 对照使用的用例盘是早期版本（SHA256=`125bacaf212260a83b934b65449d9912e6b7c3ba4d9b846ef6e8a98861631979`，制备来源见 `artifacts/M1-002-fixtures-02/manifest.json`）；ELF 用例二进制本身未变，当前用例盘为 `artifacts/M1-002-fixtures-03/manifest.json`（SHA256=`480fdfa4baad751e7cc35aa9b90ffdbffc0b77d8743c48bdd3aa4d7f640c3ef8`），差别只在 guest 侧脚本的断言划分。全部运行使用相同 Linux Image SHA256=`0ae9ba7d370de416b763b67c13d5a13fc7eeb52b3400741d54bc39410c8da5b5` 和派生 initramfs SHA256=`a918b157ee18eb7b5591d38fdd9e4b9a54f74dc02adcdb533f735da0746c2b51`。

| 畸形 ELF | Linux 的具体结果 | `exec-check reject` 状态 |
| --- | --- | --- |
| `bad-filesz` | child SIGSEGV=11，父进程仍可打印结果 | 1，不满足“显式 errno 拒绝”断言 |
| `bad-overflow` | child SIGSEGV=11，父进程仍可打印结果 | 1，不满足“显式 errno 拒绝”断言 |
| `bad-offset` | child SIGSEGV=11，父进程仍可打印结果 | 1，不满足“显式 errno 拒绝”断言 |
| `bad-interp-short` | execve 返回 errno=5，EIO | 0 |
| `bad-phentsize` | execve 返回 errno=8，ENOEXEC | 0 |
| `bad-phoverflow` | execve 返回 errno=8，ENOEXEC | 0 |

Linux 可能在 exec 已切换到新映像后以信号终止错误程序，不能把这个阶段混同为返回 errno。M1-002 应核对 x-kernel 自己的装载事务与安全错误传播，不要求逐字复制 Linux 晚期 SIGSEGV，也不能因 Linux 不返回 errno 而放弃防止整个内核 panic。前五项以外的观察口径见 [M1-002](M1-002.md#已执行验证2026-09-24)：x-kernel 修复后与 Linux 在 `bad-overflow`/`bad-offset` 上同为 SIGSEGV，在 `bad-filesz` 上仍不同（x-kernel 静默执行成功），该差异作为独立候选记录。`run.sh` 曾把六项一律断言为 reject，属测试期望错误，已拆成 `run.sh`/`run-malformed.sh`/`run-observed.sh`。

执行命令：

```sh
python3 scripts/run_linux_guest.py --run-id m1-linux-smoke --timeout 120
python3 scripts/run_linux_guest.py --run-id m1-linux-versions --guest-commands artifacts/M1-001/linux-versions.sh --timeout 180
python3 scripts/run_linux_guest.py --run-id m1-linux-failure --guest-commands artifacts/M1-001/linux-failure.sh --timeout 120
python3 scripts/run_linux_guest.py --run-id m1-linux-elf-positive --disk work/images/elf-m1.img --guest-commands artifacts/M1-001/linux-elf-positive.sh --timeout 180
python3 scripts/run_linux_guest.py --run-id m1-linux-elf-invalid --disk work/images/elf-m1.img --guest-commands artifacts/M1-001/linux-elf-invalid.sh --timeout 180
python3 -m py_compile scripts/run_linux_guest.py
```

已有 run-id 拒绝覆盖；重跑时选新的 run-id。`--guest-commands` 在独立 subshell 中执行，以最终 shell 状态判定成功；需要多项严格通过时脚本自行使用 `set -e` 和明确断言。畸形 ELF 观察脚本故意逐项打印 rc 后继续，从而完整记录六种结果。
