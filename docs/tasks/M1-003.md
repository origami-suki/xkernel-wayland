# M1-003：前置计量定义与可信度校准

- 目标：PERF-01、MEM-01、TOOL-01；首次可运行时即保存可测数据，并明确不可测项。
- 依赖：时间线设计可在 M0 同步进行；动态校准需要 M0-002；浏览器指标需要 M3。
- 范围：低干扰采样、时间点/对象定义、进程树、内存校准和统计入口；不提前做复杂优化。
- 依据：`procfs` 的 status 无 RSS，`TaskStat` 的 rss/vsize 默认 0，`getrusage.ru_maxrss=0`。详见 [内存核查](../analysis/rootfs-and-memory.md)。

## 分段完成条件

1. **首帧前准备**：统一 run-id、完整环境与命令、串口/monitor 时间线；区分 QEMU启动、kernel ready、显示服务 ready、浏览器 launch、页面请求、renderer create/ready、实际显示首帧。记录时钟域和跨域对齐误差，DOM/截图时间不直接冒充呈现时间。
2. **校准工具**：小程序分别保留/触碰固定内存、共享映射、fork、退出，验证读数变化与回收；测量进程树包含范围、共享页重复计数/去重方式、峰值采样间隔和漏采误差。按实际需要补最小可靠计量，不把完整 smaps/PSS 框架预设为首帧前置。
3. **首次可运行数据**：立即存档代码和当次原始数据；可测指标继续采满至少 5 次，不可测项写原因。计量未齐全不能延迟 first-runnable tag，也不能把 0 计为峰值。
4. **稳定后的比较入口**：启动首帧、页面加载、renderer 创建、峰值内存四类各至少 5 次，原始样本/失败样本、中位数、min/max；同一工作量、缓存、参数和日志级别。先验证采样不会显著改变受测行为。

计量数据最少包括：run-id、两个仓库提交/dirty 状态、rootfs/页面标识、QEMU/host、完整参数、事件时间、样本/单位、失败原因、统计对象与测量工具版本。不得把 host QEMU RSS 等同 guest 浏览器峰值；官方统一主机计量脚本未提供，1.5G 的正式口径仍待核对。

若以后对首版补测，保持 tag 不变，单独标注补测环境/时间/方法；若必须修改首版代码才可测，不把修改后的版本冒充原始 tag。

- 实际执行：已静态确认计量缺口，未实现或运行采样工具。
- 实现状态：计划。
- 证据状态：原始性能数据缺失。
- 用户学习/阶段验收：待确认。

## 学习实验

在 Linux 与 x-kernel 分别运行一个逐页写入 64 MiB 后释放的程序，观察 `/proc/PID/stat`、`status`、getrusage 和全局 meminfo。预期 Linux 与当前 x-kernel 的字段可用性不同；解释“字段存在”“数值非零”“统计对象正确”的区别。
