# M1-004：Wayland 的 Unix STREAM fd 传递与共享映射

- 目标：在最小 wl_shm 客户端前证明共享文件能跨进程传递、映射并正确释放；对应 COMPAT-01、WAYLAND-01。
- 依赖：M0-002 的可运行环境；M1-001 提供相同程序/ABI 的 Linux 对照。可与 Weston 补包、DRM 原语验证并行。
- 修复前静态证据：`net/knet/src/unix/stream.rs` 和 `stream/channel.rs` 未携带 ancillary；`posix/net/src/cmsg.rs` 已解析 SCM_RIGHTS，DGRAM 有状态传递，但不代表 STREAM 可用。已有 memfd/seals/shared mmap 应先测后修。
- 范围：先最小复现，再实现所需 STREAM 语义与生命周期回归；不重写所有 Unix socket 或 mmap。

## 可独立验收的步骤

1. Linux/x-kernel 运行同一两进程探针：创建 `socketpair(AF_UNIX, SOCK_STREAM)`，通过 `sendmsg` 发送标记字节和共享文件 fd，接收端 `recvmsg` 后 `mmap`；检查标记、有效接收 fd、同一对象的双向可见内容。两个进程的 fd 数字可以相同，不能据此判断是否传递成功。
2. 在现有实现复现“字节收到、fd 缺失”等实际现象，记录返回值、errno、控制数据长度、进程与文件生命周期；不能只按源码给动态用例判失败。
3. 修复已复现的语义后验证短读/分段、多 fd、控制缓冲不足、发送端关闭原 fd、接收侧提前退出、CLOEXEC 和资源回收，并对现有 STREAM 唤醒和 DGRAM 做必要回归。错误与截断行为按 Linux 对照，不统一返回成功。
4. 对共享文件验证 truncate、MAP_SHARED、seals 和父子可见性。接口探针通过后交给 M2-001 做实际 `wl_shm` pool/buffer 的提交与 release 验证；该集成结果不反过来阻塞本卡的低层接口验收。

修改内核前按其 AGENTS 和相关技能补读实现/测试约定；实际修复按独立问题拆成任务/提交，记录构建、静态检查、针对性用例及回归，不在此卡预填成功命令。

- 实际执行：2026-09-25 已运行同盘 Linux/x-kernel 探针，修复 STREAM 传递和 memfd seal 执行缺口；独立 20 项探针通过，最终提交复跑见末节。

STREAM 修复保留原 byte ring，在每个方向附加与字节位置关联的 control FIFO。短读只交付一次引用；recv 不跨越尚未消费的控制数据尾界；发送者关闭原 fd、无控制缓冲、截断、接收者关闭/退出均按所有权释放。posix 层处理 CMSG 对齐、CLOEXEC、截断后能装入的 fd、EMFILE 和控制数据拷贝失败的回滚。具体锁顺序与界限见两个 crate 的 design/security 文档。

明确限制：原有 Unix MSG_PEEK 尚未实现非消费语义；循环传递 Unix socket 形成引用环的 GC 尚未实现。这些不属于本卡 Wayland 非循环共享文件传递的通过声明。完整 Weston/wl_shm 集成仍交 M2-001，不以接口探针代替显示证据。

两项修复均已落地，验证见后续记录。所有运行使用固定 runner AArch64/TCG/2 GiB/4 vCPU，镜像来自 wayland-m0 的新 reflink 工作副本。

## memfd seal 执行路径

`m1-rights-stream-v2-20260925` 分别观察到 SHRINK 未阻止 truncate、WRITE 未阻止 pwrite。进一步添加真实 `VfsFile` 回归，修复前 `memfs` 单测为 16 通过 / 2 失败；两个失败分别返回 `Ok(())` 与 `Ok(1)`。原始日志、当时 diff 和单测 ELF/BIN 归档于 `artifacts/M1-004-seals-20260925/before-*`，不是按源码推断的失败。

根因调用链：`sys_ftruncate → VfsFile::truncate → VfsInode::set_len → MemoryAddressSpaceOperations::set_len` 直接改长度；普通写走 `MemoryNode::write_iter → generic_file_write_iter`。两者均未调用已有 shmem policy。修复在 memfs 实际修改前执行检查：写入使用 `generic_file_write_iter_with_checks`，截断在 set_len 改元数据前检查；添加 seal 也获取相同 inode data lock。锁顺序 data → seals，seal mutex 不跨数据复制持有。

自测 `make UNITTEST=y UNITTEST_CRATE=memfs,kvfs run ACCEL=n XKMAKE_ARGS='--memory 2g --smp 4 --no-net --no-vsock'` 为 197/197，见 `after-unit.log`。最终探针新增跨 EOF 写入受 GROW 限制、FUTURE_WRITE 保留既有可写映射并拒绝后续 write/新映射，共 20 项；host 和 `m1-rights-linux-final-20260925` 全部通过。x-kernel 最终独立验收 `m1-rights-seals-independent-20260925` 20/20，guest/QEMU/runner 均 0；独立 memfs/kvfs 单测 197/197，build/clippy exit 0，详见 `artifacts/M1-004-seals-independent-20260925/`。受测版本为 `cb4cf87b` 加冻结 seal 差异，最终干净提交另列。

制备脚本现在归档探针源码。早期 v1/v2/v3 也已补齐准确源码并逐一匹配原 manifest 的 source_sha256（没有修改历史 hash 或运行结果）；所有版本的实际测试二进制从开始即随 fixture 保存。

## 验证边界与复跑入口

关键调用链：`sendmsg → POSIX SCM_RIGHTS 解析/文件引用 → Unix STREAM 字节位置与控制队列 → recvmsg → 接收进程 fd 表 → MAP_SHARED`；seal 路径为 `fcntl → inode data lock → shmem policy`，与真实 write/truncate 共用串行化边界。

单项复跑可使用最终工作盘跑 `rights basic`，见 `artifacts/M1-004-seals-20260925/basic.sh`：共享文件在 fork 后才创建，发送者关闭原 fd 后，接收者仍能修改映射；发送者可观察修改和共享文件位置。`release-close` 则用另一对 socket 的 EOF 验证接收端关闭确实释放最后引用。run-id 必须新建，不覆盖历史证据。

实现验证不等于用户阶段验收。最小 wl_shm 客户端、Weston DRM 显示与输入尚未验证，由 M2 接续；M1-003 计量字段仍独立推进，不把固定 0 当作内存结果。
