# M1-005：Chromium 子进程的 no_new_privs

- 目标：复现并修复 Chromium 子进程启动时 `PR_SET_NO_NEW_PRIVS` 返回 ENOSYS 的阻塞。
- 依赖：M2-001 已完成，M3-001 实际启动暴露故障。
- 范围：prctl 参数校验、不可逆线程状态、fork/clone/exec 继承及现有 exec 凭据不提升保证；不实现完整 user namespace、seccomp 或 capabilities。
- 验收：同盘 Linux/x-kernel 的最小探针（合法/非法参数、重复设置、不可撤销、fork、线程隔离及继承、exec 与 set-ID 文件）；修复前失败/修复后通过；build/clippy、相关单测与图形/IPC回归；冻结后独立测试再提交。

## 复现证据

`m3-xkernel-default-20260925`：默认参数在 Chromium142 `credentials.cc:131` 因 ENOSYS 退出。官方对应源码将入口定位为 user namespace clone 探测；独立 userns 探针另记录，不把禁用沙箱称为隔离修复。

`m3-xkernel-no-sandbox-20260925` 与 `m3-xkernel-observe-20260925`：明确添加 `--no-sandbox` 后完成原生 Wayland registry/wl_shm pool 初始化，但出现 `prctl(PR_SET_NO_NEW_PRIVS) failed`。后一次观察到 GPU process launch failed 反复出现，最终 GPU process isn't usable 的 FATAL。未显示原始页面，未创建 first-runnable tag。

Chromium142 的 `base/process/launch_posix.cc:491–497` 在子进程 exec 前执行 SET_NO_NEW_PRIVS；ENOSYS 不在其允许的降级错误中。当前 `core/ksyscall/src/task/ctl.rs` 明确返回 ENOSYS。`Thread` 已拥有单调置位状态以及 fork/clone 拷贝，`sys_execve` 当前不处理 set-ID 文件位或文件 capabilities，只重设保存/文件系统ID并清除KEEP_CAPS。修复必须依据这条真实凭据路径验证，不能直接把未知调用改成返回成功。

官方源码及URL/hash：`artifacts/M3-001-diagnosis-20260925/chromium-source/manifest.json`。

## 同盘接口对照

- `m1-nnp-xkernel-before-20260925`：kiosk真实/有效/保存UID/GID为1000；普通clone成功，NEWUSER clone返回ENOSYS；NNP GET=0，SET(1)=-1/errno38，之后GET仍0。预期失败记录保留。
- `m1-nnp-linux-before-20260925`：普通与NEWUSER clone均成功；NNP GET=0→SET成功→GET=1。
- `m1-nnp-linux-full-20260925` 与 `m1-nnp-xkernel-after-20260925`：同一 `chromium-m3-nnp.img`，basic/fork/thread/exec/setid五类通过。basic在置位前后各检查9种非法参数；同步用pipe，没有sleep猜测。exec后检查NNP及真实/有效/保存/文件系统UID/GID共8项。
- 额外6755文件control不计入NNP通过数：Linux `applied=1` 证明fixture确实会提升权限；x-kernel `applied=0` 记录它当前根本不处理set-ID文件位。NNP=1时两者均保持全部ID=1000。不能据此宣称x-kernel已实现完整set-ID/capabilities安全模型。
- 产物与重建：`scripts/prepare_chromium_tests.py`、`tests/chromium/no-new-privs.c`、`tests/chromium/prerequisites.sh`；fixture证据在 `artifacts/M1-005-fixtures-20260925/`。镜像是M2最终盘的独立reflink，原Assets及基盘hash不变。

当前合约：no_new_privs是单调、按线程保存并在fork/clone/exec继承的标志；它约束exec获取新权限，不禁止已获授权的setuid等操作。现有exec不读取set-ID/filecap/LSM增权信息，因此满足这条限制。未来新增这些能力时必须同时接入标志，并保持回归。没有加入无意义的bool参数或统一成功兜底。
