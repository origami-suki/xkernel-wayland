# M1-008：fcntl 复制 FD 的最小编号约束

- 状态：已修复；同盘边界对照、内核单测和 M1/M2 回归通过，Chromium 正文仍空白。
- 来源：M1-007后单独启动Zygote的诊断launcher在exec之前无法把临时FD提升到指定范围。它是新探针触发的接口缺口，**尚未证明原Chromium失败依赖这个分支**。
- 目标：`F_DUPFD`/`F_DUPFD_CLOEXEC`尊重arg给定的最小新FD，并正确处理非法范围、表满和CLOEXEC。
- 优先级：用户 2026-09-25 指定从本项开始继续接口修复。

`artifacts/M1-008-diagnosis-20260925/`保存probe、编译/制备脚本、二进制与镜像hash。`m1-dupfd-xkernel-20260925`的6项全部失败：min64/100均返回4，min-1也返回4；CLOEXEC标志本身正确。`m1-dupfd-linux-20260925`同盘分别返回64/100和EINVAL，6项通过。x-kernel guest/runner1、Linux0，两者QEMU正常结束，盘hash不变。

源码入口`posix/fs/src/fd_ops.rs::sys_fcntl`的两个分支调用`dup_fd(fd, cloexec)`，没有传递arg；随后`ProcessResources::duplicate_file`只选择普通空闲槽。不得通过在调用方重试/占位大量低FD来假装修复。

验收前扩展边界：有洞/已占用最小槽、负数/超上限、坏源FD、CLOEXEC、共享offset、FD表满与失败无泄漏。先核对RLIMIT_NOFILE和现有FdTable分配约束，再做小范围实现、Linux对照、内核单测及独立回归。
