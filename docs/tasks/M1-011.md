# M1-011：未知 fcntl 命令的错误返回

- 状态：已修复；同盘对照与干净提交回归通过，浏览器首帧未通过。
- 目标：未知命令在有效 FD 上返回 EINVAL，在不存在的 FD 上优先返回 EBADF；不修改描述符或文件状态。
- 范围：`posix/fs/src/fd_ops.rs` 的兜底分支、自编 C 探针、制备与文档。文件锁等已知命令留给独立任务，不以本项声称已实现。
- 授权：用户明确允许自行实现本批已知接口缺口，并要求不再逐项查找上游。
- 应用关系：原浏览器日志尚未看到未知 fcntl 命令；本项是已确认成功占位的合同修复，白屏因果尚未证明。

`tests/chromium/fcntl-unknown.c` 在动态与静态版本中测试三种未知 cmd、两种 arg、有效/关闭/负源 FD 的 18 种组合，以及标志和空闲槽没有变化。制备工作盘 `work/images/chromium-m1-fcntl-unknown-v1.img`，保留赛方用户态和原页，仅部署自编探针。证据根目录 `artifacts/M1-011-fcntl-unknown-20260925/`。

最小验收：相同盘 Linux 通过、修复前 x-kernel 失败、修复后通过；构建和 clippy；F_DUPFD 回归；本批浏览器复跑按 monitor 原图判断，不以 errno 通过代替正文首帧。

- `m1-fcntl-unknown-linux-20260925`：动态/静态各 20 项通过。
- `m1-fcntl-unknown-before-20260925`：干净 `ec9df016`，两版本各失败 18/20 项；坏 FD 和未知 cmd 均曾被返回成功。
- `m1-fcntl-unknown-after-20260925`：两版本各 20 项通过；`m1-fcntl-dupfd-regression-20260925` 两版本各 71 项及 exec 子检查通过。
- `make build`、提交 hook 的 fmt/clippy 通过。提交后重新构建干净内核，`m1-fcntl-clean-20260925` 一轮重跑上述两个动态/静态探针均通过。所有通过的 guest/QEMU/runner=0；修复前 guest/runner=1、QEMU=0。
- 本项不新增镜像中的第三方程序、不改文件锁分支。原警告保留，供 missing-interfaces 清单记录；只对未知命令分支先验证源 FD，再返回 EINVAL。

命令入口：`python3 scripts/run_linux_guest.py` / `python3 scripts/run_guest.py --bundle <记录的 bundle>`，共同参数 `--disk work/images/chromium-m1-fcntl-unknown-v1.img --guest-commands tests/chromium/fcntl-unknown.sh --timeout 90`；run-id 使用上表名字，重跑须用新名字。完整命令、输入哈希和退出状态保留在每个 `artifacts/runs/<run-id>/`。

浏览器诊断 `m3-fcntl-stages-20260925` 仅增加 `--v=1`，8 张 monitor 图均黑，不能把较短的详细日志观察窗口与前次长观察直接比较成显示回归。观察完成、RAW_LOG 完整；Chromium 清理使用强制 KILL，guest/runner=1、QEMU=0，最终正常关机。日志新增确认 browser TID 63 调用 `FileURLLoader::Start` 请求原始 index；PID 86（明确 NetworkService）和 PID 98（继承 zygote cmdline，具体角色尚未证明）进入 `ChildThreadImpl::EnsureConnected()`。

核对 Chromium 固定 142.0.7444.59 的只读源码：该函数是连接超时回调，直接以状态 0 终止进程，`OnChannelConnected` 会撤销该回调。因此它不是“连接成功”日志，而是子进程 IPC 连接未及时完成的证据。源码副本在本项 evidence 的 `chromium-source/`，来源：

- https://github.com/chromium/chromium/blob/142.0.7444.59/content/child/child_thread_impl.cc#L741
- https://github.com/chromium/chromium/blob/142.0.7444.59/content/browser/loader/file_url_loader_factory.cc#L474

下一项最小定位应围绕子进程连接握手的 Unix socket 消息、FD 传递与等待唤醒；尚不能由此认定具体内核模块，也不声称 renderer 已解析原页。
