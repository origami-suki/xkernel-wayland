## 第一处定位

从当前代码 `posix/mm/src/mmap.rs::sys_munmap` → `mm/memspace/src/aspace.rs::unmap` 及实际命中的 VMA/backend 路径开始。只给必要阶段增加有界统计：

1. 关联长调用 PID/TID、范围/页数、映射类型；不靠继承的 zygote cmdline 猜身份。
2. 区分锁等待和实际 CPU，定位 VMA/页表处理、TLB 失效、页引用/回收等阶段中实际占用的部分。这些是待排查边界，不是已确认根因。
3. 使用能够复现该分支和规模的自编 C 最小用例；再回到同一 Chromium 原页核对。

首个假设：慢调用覆盖的虚拟范围显著大于实际映射页数，逐页从根查表产生可避免工作。先用未优化内核测量完全未触碰、稀疏触碰和密集触碰的匿名映射，分别改变虚拟范围与实际页数；实际 Chromium 补充分段证据。若证据不支持该假设，停止该算法改动并记录实际主导阶段，不把 Linux 实现本身当作本项目根因证明。

## 最小实现与正确性边界

1. 页表层提供允许空洞的范围解除映射：跳过缺失子树，复用已定位叶表；不分配下级页表，不回收中间页表，不改变现有单页/连续映射 API 契约。
2. 现有 `unmap_region` 遇空洞报错，不能直接替代 backend 循环。新接口明确对齐、溢出、地址边界、实际叶页大小及大页部分重叠的行为，确保边界外映射不受影响。
3. 只接入确认命中的私有匿名/私有文件映射公共路径；保持对象 detach、COW 引用、PTE 修改、TLB finish 和最终物理页释放顺序。空洞可跳过，其他错误不能统一吞掉。
4. 不移植 Linux 源码或整套 MM 数据结构；以已核对的算法和生命周期约束在当前 Rust 抽象内实现。保留当前地址空间锁、ASID 刷新策略和第三方用户态。
