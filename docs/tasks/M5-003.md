## Leader / worker 分工与资源约束

- Leader 负责确定目标、分配文件归属、核对证据、控制 QEMU 运行权限与最终整合。
- 复扫 worker 核对已有五轮 candidate 的源码对应关系，优先重算原始记录；需要新运行时先做单轮诊断。
- 检索 worker 只读分析 openat 的查找、权限、元数据与缓存路径，提出能够区别假设的最小测量。
- **同一时刻全机最多一个 QEMU。** 只有持有 leader 运行权限的 worker 可以启动；每次启动前检查现有 QEMU，发现非本任务实例时等待，不终止他人的进程。其他 worker 不运行 QEMU；性能运行期间不并发内核构建。
- 实现与独立验收分开；最终补丁冻结后交给另一个 worker，在独立源码/构建输出/工作盘上验证，leader 阻塞等待结果。

## 推进与停止条件

1. 核对原始统计、输入和源码对应关系；有充分等价证据时复用 M5-002 的五轮优化后样本，不将旧样本写成当前新跑。
2. 输出新的 CPU 排名、次数、错误率、进程分布与统计覆盖限制，选一个目标。
3. 若仍以 openat 为首要目标，先区分成功/失败路径及主要成本阶段。已有聚合不能回答的问题，使用有界诊断或自编 C 探针补证据。
4. 只有根因数据支持才形成最小改动；疑似内核缺陷先按 AGENTS.md 查上游 issue/PR。候选补丁获取、冻结、独立验证和等待遵守现有流程。
5. 优化验收包含相关语义/边界回归、build/fmt/clippy/hygiene、原页 monitor 显示与清理；正式性能 before/after 各至少五次，固定统计开关及环境，保留失败样本、中位数和范围。
6. 证据不足时记录已知事实、排除项及下一项最小验证；不叠加缓存、调度器或其他 syscall 的猜测性改动。
