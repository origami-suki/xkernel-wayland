### A：观测口径与校准

- 先核实镜像内 Linux 的 config/tracefs/available_events，冻结两侧共有字段与缺口。
- 复用 x-kernel 已有 tracepoint/CPU 账本，最小扩展生命周期、状态转换、就绪/阻塞原因、时钟与丢失计数；采用有界低干扰记录。
- 校准 run/sleep、runnable 竞争、pipe/futex 唤醒、fault、线程退出/迁移及 IRQ 归属；验证事件顺序、窗口闭合、每 CPU 容量、对象生命周期与丢失检测。
- 预先记录时钟对齐方案及误差范围；保留 unknown，不按墙钟比例分摊未知的片段 CPU。
- 完成实现后冻结，由独立 agent 在隔离源码、构建输出及工作盘验证；主 agent 交接后阻塞等待。只测本项观测能力，不扩大为通用调度优化。

### B：当前 Linux/x-kernel 串行启动诊断

- 同一冻结盘、用户态、页面、CPU/内存/设备、日志、profiler 开关及缓存策略。全机最多一个 QEMU；运行期间不并发构建。发现他人 QEMU 时等待，不终止。
- 先一对串行 Linux→x-kernel 验证覆盖；合格后反转顺序复核关键段。此为诊断，不作为少于五轮的正式性能结论。
- 同次采集 launch/exec、子进程与 IPC ready、导航、页面处理、提交及 monitor 原图；补入 Weston/内核 worker 和 host QEMU vCPU 调度，防止漏掉树外生产者或宿主抢占。
- 分别输出互斥线程 CPU/ready/blocked/unknown 预算与首帧依赖路径。定位最长未知段后才定向补等待对象、请求/响应或资源生产者事件。
- 校准新增追踪扰动；不把追踪线程 CPU 扣除值当成无追踪表现，也不重启 M1-013 已由用户取消的独立五开五关验收。

### C：选择一个优化点

- 前提是关键阶段、依赖边、生产者成本及相同阶段 Linux 差异有原始证据；高 syscall CPU 排名本身不足以进入优化。
- 出现具体语义缺陷时，按 AGENTS.md 的上游查找/候选独立验证流程处理；不因本轮性能假设扩大到全内核修补。
- 正式收益须有针对性语义测试、必要集成回归、原页 monitor 与正常退出；固定条件 before/after 每侧至少五轮，中位数、范围和失败样本齐全。
