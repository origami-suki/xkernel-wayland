# M5-005：资源文件读取差异的最小复现

- 目标：继续 M5-004，将匹配的 3003 次 `ReadAtCurrentPos` CPU 差异缩小到可复现的读取或观测成本；尚不认定为首帧关键路径。
- 起点：集成 `9021a2df`，内核 `855a8c3c`；沿用 `task/M5-004-perfetto-linux-compare`，保留既有用户 `AGENTS.md` 修改。
- 范围：自编 C 探针、制备/运行/分析脚本和文档；同盘 x-kernel/Linux 对照。首轮不修改内核或第三方软件，不变更原始 Assets、资源文件或测试页。
- 固定 AArch64/cortex-a76、TCG、4 vCPU、2 GiB，复用 M5-004 准确 bundle 与 rootfs 派生工作盘；全机同时最多一个 QEMU，不并发构建。

## Leader / worker 与验收

1. Probe worker 核对 Chromium 固定版本读取语义及实际资源文件，只部署项目探针；先做无逐调用计时的分批读取，再单独测逐调用时钟成本及有限粒度/缓冲区对照，验证字节数、调用数及内容校验值。区分首次读取与后续复用，不声称已控制冷缓存。
2. Source worker 只读梳理 read→VFS→缓存/复制边界，并有限查找相关上游 issue/PR（含关闭/合并）；访问失败与未找到分开，不因相似症状直接取补丁。
3. Probe worker 独占 QEMU 权限，保留两侧实际命令、版本、原始日志、输入与产物哈希和退出状态；首轮每侧一个 guest、有限重复，仅为诊断，不是正式优化收益。
4. 测量冻结后交独立 reviewer 核对源码、原始输出及结论；leader 使用 Agent 等待工具阻塞等待。
5. 数据足以定位时收束；确需内核插桩或相关候选补丁时先明确最小范围，遵守项目冻结、隔离、独立验证流程，不叠加猜测性优化。
6. 归档新增关键证据、更新文档和项目检查后提交，不推送。

状态：单线程初轮及有界线程数追加均通过独立审查，定位闭环完成；未修改生产内核或验证上游候选。

## 单线程初轮与追加边界

- 纯 4 KiB 主资源读取 CPU：x-kernel 80.827 / 91.824 ms，Linux 14.550 / 13.824 ms；clock-only 为 169.674 / 175.410 ms 对 33.882 / 32.969 ms。资源、字节数、wrapper/raw read 次数、后读校验、输入盘不变及正常退出均通过。
- 探针运行前 shell SHA 校验已预读资源；计时后独立 FNV 校验不证明计时 buffer 每字节内容。每侧两次为有序模式内重复，不是独立冷启动。
- 该微测远未复现 Perfetto 5.782 秒的读取累计 CPU。源码发现当前每 trap 的 CPU timer 轮询会扫描所有进程线程，位于已有 syscall profiler 范围之外；仅为待验证假设。
- 追加只改变休眠辅助线程数（0 / 8 / 32），保持资源和 4 KiB 读取量固定，batch / clock-only 两模式；使用阻塞同步确保辅助线程就绪，无忙等，测量外创建/唤醒/回收。两侧各一个新 guest、每格两次；不改内核，不并发 QEMU。
- 上游 !813 / !869 元数据已有限检索并保留，尚未获取补丁；只在运行证据支持时另按项目候选验证流程处理。
